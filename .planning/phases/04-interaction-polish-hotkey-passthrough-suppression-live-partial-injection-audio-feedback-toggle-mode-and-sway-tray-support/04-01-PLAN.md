<task type="auto">
  <name>Task 2: Grab-and-forward input passthrough in EvdevHotkeyListener</name>
  <files>murmur/hotkey/evdev.py</files>
  <action>
Implement the grab-and-forward pattern in `EvdevHotkeyListener` per the locked user decision.

1. **Constructor changes:** Accept `bindings: list[HotkeyBinding]` instead of `modifiers`/`trigger`/`mode`. For each binding, resolve `_modifier_codes: set[int]` and `_trigger_code: int` from ecodes. Store as a list of resolved binding structs (e.g., a `_ResolvedBinding` namedtuple or dataclass with `modifier_codes: set[int]`, `trigger_code: int`, `action: str`).

2. **Grab + UInput in start():** After opening each device, call `dev.grab()` to EVIOCGRAB the physical keyboard. Create a matching virtual device via `UInput.from_device(dev, name=f'murmur-{dev.name}')`. Store `(dev, uinput)` pairs in `self._devices` (change the type from `list[Any]` to `list[tuple[Any, Any]]`).

3. **Event forwarding in _listen_loop:** For each event read from a device:
   - If `event.type != EV_KEY`: forward unconditionally via `uinput.write_event(event); uinput.syn()`
   - If `event.type == EV_KEY`: check against all resolved bindings. If it matches a hotkey trigger while all modifiers are held, suppress (do not forward) and dispatch the action. Otherwise, forward the event.

4. **Modifier state management on hotkey fire:**
   - When a hotkey binding fires (trigger key-down with all modifiers held): before dispatching, inject synthetic key-up for each held modifier code into the UInput so the compositor's modifier state is cleared. Then call `_dispatch_action(binding.action)`.
   - When a hotkey trigger is released AND it was previously suppressed: inject synthetic key-down for the modifiers that are physically held to restore compositor state. Then call `_dispatch_release(binding.action)`.
   - Track which trigger codes are currently "suppressed" (hotkey is active) in a `self._suppressed_triggers: set[int]` to know when to restore modifiers on release.

5. **Cleanup in stop():** For each `(dev, uinput)` pair: `dev.ungrab()`, `uinput.close()`, `dev.close()` (all wrapped in `contextlib.suppress(OSError)`).

6. **Suppress modifier-only events:** When a modifier key that is part of ANY binding is released while a trigger is suppressed, do NOT forward the modifier release (it would confuse the compositor since we already sent a synthetic release). Track this carefully: only suppress modifier forwarding while a hotkey trigger is actively suppressed.

7. **Update logging in start():** Log all bindings with their action names and key combos.

**Important anti-patterns to avoid (from research):**
- Never call `dev.ungrab()` while modifiers are held
- Always call `uinput.syn()` after each forwarded event
- Forward `SYN_REPORT` events -- they come from the device read loop naturally
