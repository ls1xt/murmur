<task type="auto">
  <name>Task 2: Create .pre-commit-config.yaml</name>
  <files>.pre-commit-config.yaml</files>
  <action>
Create `.pre-commit-config.yaml` in the repo root with the following content. Use the latest stable versions for each hook repo — verify with `uv run pre-commit autoupdate` after writing the initial file, or hardcode these known-stable versions:

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.9.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-added-large-files
        args: [--maxkb=500]
      - id: check-case-conflict

  - repo: https://github.com/Yelp/detect-secrets
    rev: v1.5.0
    hooks:
      - id: detect-secrets
        args: [--baseline, .secrets.baseline]
```

Notes on hook selection (per CONTEXT.md decisions):
- `ruff` with `--fix` runs lint and auto-fixes; `ruff-format` runs formatter
- `trailing-whitespace` and `end-of-file-fixer` are standard hygiene
- `check-added-large-files` rejects files > 500 KB (per CONTEXT.md: 500 KB limit)
- `check-case-conflict` prevents case-insensitive filesystem issues
- `detect-secrets` scans for API keys, tokens, private keys with a baseline

CONTEXT.md also mentions `check-jupyter` and forbidding `.ipynb` files. Since the repo has no notebooks and the `check-jupyter` hook validates (not forbids) notebooks, SKIP `check-jupyter` — it serves no purpose on a repo with no notebooks. The `--fix` in ruff handles most auto-fixable lint issues.

Do NOT include pyright as a pre-commit hook (per RESEARCH.md recommendation: pyright in pre-commit creates isolated env that doesn't inherit project stubs; run pyright directly in CI instead).

After writing the file, run `uv run pre-commit autoupdate` to get latest rev hashes — this updates the `rev:` fields to the latest tagged releases. Accept the updated versions.
  </action>

<task type="auto">

  <action>
Generate the detect-secrets baseline file so the detect-secrets hook passes on the existing repo:

```bash

```

If `detect-secrets` is not yet available as a direct command, install it via pre-commit's environment or add it temporarily:
```bash

# Then generate baseline after the first install:

```

After generating .secrets.baseline, run the full pre-commit suite to confirm it passes:
```bash
uv run pre-commit run --all-files
```

If `ruff --fix` or `ruff-format` modifies files (exit code 1 because fixes were applied), that is expected behavior — re-run pre-commit once more after the fixes:
```bash
uv run pre-commit run --all-files
```

The second run should exit 0 (all hooks pass, no more modifications to make).

If any hook fails unexpectedly (not ruff auto-fix):
- `trailing-whitespace` or `end-of-file-fixer` failures: re-run; they auto-fix on first run too
- `check-added-large-files`: check `git ls-files | xargs du -sh | sort -h` to find large files; add to .gitignore if needed
- `detect-secrets`: if it flags false positives in existing files, re-generate baseline after audit: `uv run detect-secrets scan > .secrets.baseline`

Do NOT add `uv.lock` or `.planning/` directories to pre-commit's exclusion list without explicit reason — let the hooks run on all files.
